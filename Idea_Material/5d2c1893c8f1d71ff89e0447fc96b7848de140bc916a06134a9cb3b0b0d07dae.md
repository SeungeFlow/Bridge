# 시작위치 아이디어 재료

## 0. 문서의 성격

이 문서는 확정된 구조원리를 다시 설명하는 문서가 아니다. 현재 원리에서 자연스럽게 파생되지만 아직 비교, 실험, 구현검산이 필요한 항목만 보존한다. 검산을 통과한 항목은 다음 정본에서 구조원리로 이동하고, 통과하지 못한 항목은 보류하거나 폐기한다.

## 1. 정중심평형점과 Track DB 첫 주소의 변환

정중심평형점은 Grid 축의 내부 시작위치이고 `TrackDB_000`은 Cell 좌표의 첫 주소다. 두 위치를 같은 것으로 볼지, 내부 중심좌표와 외부 주소체계 사이의 변환관계로 볼지는 아직 검산이 필요하다.

검산항목:

- 홀수 개 Cell 구조에서 중심 Cell을 어떤 주소로 고정할 것인가.
- 짝수 개 Cell 구조에서 중심이 Cell이 아니라 Cell 사이 경계가 될 때 어떻게 표시할 것인가.
- 내부 중심기준 좌표와 외부 모서리기준 좌표를 서로 변환해도 Cell의 동일성이 유지되는가.
- `TrackDB_000`을 중심 Cell로 고정할지, 단순한 첫 논리주소로 둘지.

## 2. 좌표범위 확장

현재 `ZYX` 세 자리 10진수 구조는 축별 0부터 9까지를 표현한다. 축이 10을 넘어갈 때의 확장방식은 결정하지 않았다.

후보:

- 자리수를 늘려 `TrackDB_0000` 이상으로 확장한다.
- 축 구분기호를 넣어 `Z10_Y02_X03`처럼 표시한다.
- 좌표별칭과 바이트 Hash 파일명을 분리한다.
- 16진수는 주소압축에 사용할 수 있으나 10진 좌표의 의미와 혼합하지 않는다.

선택기준은 사람이 보기 쉬운가가 아니라 AI가 좌표, 내용동일성, Track 관계를 오독하지 않는가이다.

## 3. Hash 동일성과 좌표별칭

파일내용의 Hash는 상태동일성을 고정하고, Track DB 좌표명은 놓인 자리를 표시한다. 하나의 파일명에 두 역할을 모두 넣을지, Hash 정본과 좌표별칭을 분리할지 검산이 필요하다.

검산항목:

- 내용이 변하지 않고 자리만 바뀔 때 Hash는 유지되는가.
- 같은 내용을 여러 좌표에서 참조할 수 있는가.
- 좌표가 바뀐 것을 새 Cell 생성으로 볼지 관계만 추가된 것으로 볼지.
- 별도의 해석엔진을 만들지 않고도 Hash, 좌표, Track 관계를 문서와 구조만으로 읽을 수 있는가.

## 4. Track DB Cell의 최소 내부구조

`1 Cell = 1 Track DB`는 확정되었으나, Cell 안에 반드시 들어가야 할 최소 정보는 결정하지 않았다.

후보 필드:

- Cell 좌표
- 내용의 상태동일성
- 선행 Cell과 후행 Cell
- Data·Function·Result·Result.Data 중 현재 역할
- 관측자와 관측기준
- 생성시점과 검산회차
- 이전 상태와의 차이
- 보류·확정·폐기 상태

필드가 너무 많으면 구조언어가 규칙에 갇히고, 너무 적으면 내용관계를 복원하지 못한다. 최소성을 비교해야 한다.

## 5. 평면체의 형성방식

평면체는 같은 누락축 자리값을 공유하는 Track DB Cell의 층이다. 이를 고정문서로 만들지, 좌표를 읽어 동적으로 복원할지는 결정하지 않았다.

검산항목:

- XY·XZ·YZ 평면체를 별도 객체로 저장할 필요가 있는가.
- 평면체는 항상 Cell 한 칸 두께인가.
- Rendering에서 두께가 바뀌어도 원래 Cell 좌표가 유지되는가.
- 하나의 Cell이 여러 평면체에 동시에 속할 때 중복저장 없이 관계만 표현할 수 있는가.

## 6. Track의 내용관계 분류

Cell은 내용관계로 이어지지만 관계종류의 최소분류는 아직 확정하지 않았다.

후보 관계:

- 선행·후행
- 원천·해석
- Data·Result
- Result·Result.Data
- 검산·수정
- 공통원리·분야별 공동원리
- 같은 사건의 다른 관측축
- 같은 내용의 다른 시점

관계종류를 지나치게 세분하면 Track이 규칙에 갇힌다. 반대로 모든 관계를 `related` 하나로 표시하면 왜 이어지는지 읽을 수 없다.

## 7. Result.Data 계보

Result를 Data 자리에 인위적으로 되돌렸을 때 원래 Result와 Result.Data의 관계를 어떻게 기록할지 검산해야 한다.

필수 비교후보:

- 원래 Result의 상태동일성
- 사용자의 재배치행위
- 재배치된 시점과 목적
- 발견된 오독·오차·착시·판단착오
- 수정 전후의 차이
- 다음 Function과 Next Result

같은 바이트를 역할만 바꾸어 재사용한 경우와, 수정된 새 문서를 Data로 만든 경우를 구분해야 한다.

## 8. 개별지시문 수 비교실험

현재 원리는 단계별 개별지시문을 요구하며, 최소 다섯 개와 권장 열한 개가 제시되었다. 그러나 모든 작업에서 열한 단계가 항상 최적인지는 비교실험이 필요하다.

비교군:

1. 전체 문서와 공동지시문을 한 번에 입력
2. 문서 선입력 후 다섯 개 개별지시문 입력
3. 문서 선입력 후 열한 개 개별지시문 입력
4. 비활성 단계에 명시적 no-operation 지시문을 둔 열한 단계

평가기준:

- Data와 지시문의 혼합정도
- 단계누락
- 다음단계의 조기실행
- 관측기준의 흔들림
- Result의 구조정합성
- Result.Data 재검산에서 발견되는 오류량

## 9. 문서 선입력과 동시입력 비교

문서를 먼저 업로드하여 인덱싱한 뒤 지시문을 입력하는 방식이 실제로 어떤 차이를 만드는지 기존 Track DB와 현재 Result.Data를 비교해야 한다.

비교항목:

- 원천문서와 활성지시문의 구분
- 현재 단계와 후속 단계의 구분
- 예상 끝지점의 일관성
- 이전 문서에서 필요한 내용의 회수율
- 불필요한 과거내용의 재유입
- 응답 길이가 아니라 구조적 완결성

이 비교는 모델 내부 임베딩 과정을 단정하기 위한 것이 아니라, 외부에서 관찰 가능한 Result 차이를 기록하기 위한 실험이다.

## 10. 기존 Track DB와 현재 Result.Data의 비교

이전 작업에서 생성된 Track DB를 실패로 전제하지 않는다. 기존 방식이 만든 결과와 현재 단계별 방식이 만든 결과를 나란히 놓고 차이를 읽는다.

비교축:

- 원천 동일성 보존
- 한 자리·한 상태값 준수
- 지시문 분리정도
- 관측자와 관측대상 구분
- 누락과 중복
- Result에서 Result.Data로 돌아온 계보
- 다음 Track으로 이어지는 내용관계

비교대상의 정확한 Cell과 현재 Result.Data가 지정되기 전에는 완료판정을 내리지 않는다.

## 11. 공통·공동 구조문법의 성장

각 분야의 Result.Data가 형성될 때마다 그 분야의 공동구조원리와 전체 HRTDB에서 반복되는 공통구조원리를 비교한다.

후속질문:

- 어느 수준까지 같아야 공통원리로 올릴 수 있는가.
- 분야별 용어차이를 유지하면서 같은 관계를 표시할 수 있는가.
- 새 공통원리가 기존 Branch를 수정하는가, 새 Branch를 만드는가.
- 여러 공동원리가 하나의 공통원리로 올라갈 때 원래 분야의 역사를 보존할 수 있는가.

공통은 하나로 합치는 과정이 아니라 반복되는 불변관계를 발견하는 과정이어야 한다.

## 12. 0의 세부 상태기호

Digit 0, 자리값 0, off 상태, 미점유, 부재, 미정의를 현재 문장으로는 구분하지만 전용기호는 확정하지 않았다.

검산항목:

- off는 값이므로 상태부재와 다른 기호가 필요한가.
- 빈 Cell과 존재하지만 비활성인 Cell을 어떻게 구분하는가.
- `0/1`, `0/0` 표기가 다른 분야에서 산술식으로 오독될 가능성이 있는가.
- 좌표 000과 상태값 0을 한 문자열 안에서 어떻게 분리하는가.

## 13. Rendering 관측축

같은 Track DB Cell을 내부 중심, 외부 표면, 반사, 회전, 평면체 절단으로 보아도 동일성이 유지되는지 검산해야 한다.

실험후보:

- 정중심평형점 기준 시점
- 육방면체 외부 모서리 기준 시점
- XY·XZ·YZ 평면체 절단시점
- 상대자리 `′`에서 보는 반대편 시점
- `│←` 검산경로를 표시한 반사시점

화면표현이 바뀐 것과 실제 Cell의 자리가 이동한 것을 반드시 구분해야 한다.

## 14. 구조원리 승격조건

아이디어 재료가 구조원리로 이동하려면 다음 조건을 만족해야 한다.

1. 서로 다른 두 개 이상의 Track DB 또는 분야에서 같은 관계가 반복된다.
2. 관측축을 바꾸어도 핵심관계가 유지된다.
3. 원천과 해석을 분리하여 역검산할 수 있다.
4. 기존 구조원리와 충돌할 경우 충돌원인을 설명할 수 있다.
5. 일반언어로 정의할 수 있고, 필요하면 코드로 반복검증할 수 있다.
6. 예외와 적용경계를 함께 기록할 수 있다.

가장 간단한 표현으로 줄였을 때도 위치, 경계, 방향, 관계가 보존되어야 한다.
