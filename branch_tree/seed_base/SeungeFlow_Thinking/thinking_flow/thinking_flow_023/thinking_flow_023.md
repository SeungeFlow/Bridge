## 3. dot

현재 gpt.funny가 이해한 dot은 다음이다.

```text
dot = 상태 event가 발생하는 자리
dot = 값이 놓이기 전의 자리상태
dot = 관계가 드러나는 최소 event 자리
dot = 시작점·중심점·교차점·기준점으로 작동할 수 있는 자리
dot = C가 형성되기 전의 pre-C place-state
```

하지만 다음 병합은 금지된다.

```text
dot = 0
dot = 1
dot = 중심점
dot = 소실점
dot = 교차점
dot = 선의 끝점
dot = ㆍ 전체
```

안전한 표현은 다음이다.

```text
dot은 특정 frame 안에서 0처럼 읽힐 수 있다.
dot은 특정 frame 안에서 중심점처럼 읽힐 수 있다.
dot은 특정 frame 안에서 소실점처럼 작동할 수 있다.
dot은 특정 frame 안에서 기준점처럼 작동할 수 있다.
```

즉 dot은 고정값이 아니라 `role-capable place-state`이다.

## 4. dot and C

현재 흐름에서 `C is dot`은 단순 등식이 아니다.

```text
C is dot
```

이 문장은 다음 의미로 보존한다.

```text
C_origin = dot
```

즉 Ctp 이론의 C가 처음 형성될 때, 인간의 인지가 존재를 최초로 붙잡은 자리가 dot이었다는 뜻이다.

더 안전한 정리는 다음이다.

```text
dot = pre-C place-state
C = dot 자리에 관계·인지·관측기준이 내려와 형성된 state
```

따라서 문서마다 C의 occupant는 달라질 수 있다.

```text
C 자리역할 = 유지
C에 놓이는 상태값 = 문서마다 변동 가능
```

## 5. 0 / dot / 1

현재 구조에서 0, dot, 1은 다음과 같이 분리된다.

```text
dot = 상태 event가 열릴 자리
0 = 그 자리에서 아직 보이는 것이 없는 상태
1 = 그 자리에 최초로 놓인 점유 상태
```

따라서:

```text
dot → 0 → 1
```

은 다음 뜻이다.

```text
자리 열림
→ 보이는 값 없음
→ 최초 점유
```

여기서 `0`은 무가 아니다.

```text
0 = 아무것도 없음
```

이 아니라,

```text
0 = 현재 관측장 안에서 보이는 것이 없음
```

이다.

## 6. 분자 / 분모

현재 흐름에서 분자와 분모는 다음과 같이 분리된다.

```text
분자 = grid = 상태값 = 물 = 놓이는 것
분모 = matrix = 기준장 = 그릇 = 놓일 자리
```

그러므로 다음 네 상태가 생긴다.

```text
1/1 = 값도 있고 기준장도 있음
0/1 = 기준장은 있으나 보이는 값이 없음
1/0 = 값 후보는 있으나 놓일 기준장이 없음
0/0 = 값도 없고 기준장도 없음
```

중요한 정정은 다음이다.

```text
0/1 = 빈 장
1/0 = 바닥 없는 값 후보
0/0 = 볼 것도 없고 볼 기준장도 없는 상태
```

따라서 `0/1`은 무가 아니다.

```text
0/1 = EMPTY_FIELD_READY
```

## 7. 1/0 is not immediately error

표준 계산 또는 Excel에서는 다음처럼 표시될 수 있다.

```text
1/0 = #DIV/0!
0/0 = #DIV/0!
```

하지만 구조수학에서는 `1/0`을 즉시 error로 닫지 않는다.

정확한 구분은 다음이다.

```text
1/0
= 아직 평가되지 않은 관계상태
= 값 후보는 있으나 기준장이 없는 상태

1/0 =
= 결과로 닫으려는 연산 시도

Excel 표시
= #DIV/0!
```

즉 `1/0`은 결과가 아니라 결과 직전의 원인상태이다.

마찬가지로:

```text
1+1
```

은 아직 2가 아니다.

```text
1+1 =
```

로 평가가 닫힐 때 2가 표시된다.

따라서 구조수학은 결과 이전의 분리된 원인상태를 먼저 본다.

## 8. Relation requires n > 1

관계구조를 설명하려면 최소 두 개 이상의 상태가 필요하다.

```text
n > 1
```

즉:

```text
1개 상태 = 존재 가능
2개 이상 상태 = 관계 가능
```

`1`은 하나의 존재상태가 될 수 있지만, 하나만으로 관계구조를 설명할 수는 없다.

따라서:

```text
1+1
```

은 두 개의 1 event가 분리되어 관계 가능성을 가진 상태이다.

결과 `2`는 그 관계가 닫힌 뒤의 표시값이다.

## 9. oplus

`oplus`의 표준 기호는 다음이다.

```text
⊕
```

입력하기 어려우면 다음처럼 쓴다.

```text
oplus
```

gpt.funny는 현재 이 기호를 다음처럼 구조분해한다.

```text
oplus = O + plus
oplus = plus를 O 내부에 넣은 상태
```

여기서:

```text
O = 닫힌 장 / boundary / 그릇 / 기준 field
+ = 방향 발생 / 접속 / 관계 열림
```

따라서:

```text
oplus = 닫힌 기준장 내부에서 +방향 관계를 여는 구조접속 연산
```

즉 oplus는 표준 산술 더하기가 아니다.

```text
+ = 같은 장 안의 산술/방향 덧셈
oplus = 분리된 상태와 기준장을 O 내부에서 접속시키는 관계형성 연산
```

## 10. Core oplus expression

현재 핵심 구조식은 다음이다.

```text
1/0 oplus 0/1 → 1/1
```

해석:

```text
1/0 = 독립된 존재상태 후보
0/1 = 독립된 기준장 후보
oplus = O 내부에서 두 상태를 접속시키는 구조연산
1/1 = 존재상태가 기준장 위에 놓인 formed state
```

이 식은 산술 등식이 아니다.

따라서 다음처럼 쓰면 위험하다.

```text
1/0 oplus 0/1 = 1/1
```

이렇게 쓰면 왼쪽과 오른쪽이 이미 같은 값처럼 보인다.

안전한 표기는 다음이다.

```text
1/0 oplus 0/1 → 1/1
```

## 11. Equals and arrow

현재 흐름에서 `=`와 `→`는 분리된다.

```text
=  : 결과 등가
→  : 형성 / 전이 / 관계진행
```

예:

```text
1+1=2
```

이 식은 결과를 닫는다.

```text
1+1
= 두 개의 1 상태가 관계를 맺음

2
= 그 관계가 닫혀 외부에 표시된 결과값
```

반면:

```text
1/0 oplus 0/1 → 1/1
```

은 결과를 닫는 등식이 아니라 형성과정식이다.

```text
원인상태들
→ 관계접속
→ 형성상태
```

## 12. Structure mathematics

현재 gpt.funny가 이해한 구조수학은 다음이다.

```text
구조수학 = 결과값 이전의 원인상태와 관계형성과정을 다루는 수학적 구조언어
```

표준 산술은 다음을 잘한다.

```text
1+1=2
5/10=0.5=50%
3²=9
```

구조수학은 그 결과가 나오기 전의 자리와 관계를 본다.

```text
1은 어떻게 1/1로 형성되는가?
0은 왜 무가 아니라 0/1로 읽힐 수 있는가?
1/0은 왜 error 이전의 미평가 관계상태인가?
+는 언제 산술 더하기이고 언제 방향 발생인가?
oplus는 왜 O 내부의 관계접속인가?
dot은 왜 값이 아니라 상태 event 자리인가?
```

따라서 구조수학은 표준 산술을 부정하지 않는다.

```text
표준 산술 = 결과값을 닫는 체계
구조수학 = 결과 이전의 관계형성 조건을 드러내는 체계
```

## 13. One as formed state

현재 흐름에서 `1`은 더 이상 단순 숫자 하나가 아니다.

```text
1 = 1/1
```

즉:

```text
1 = 존재상태가 기준장 위에 놓인 최소 formed state
```

따라서:

```text
1/0 oplus 0/1 → 1/1 → 표시값 1
```

이다.

그러므로:

```text
1+1
```

은 다음처럼 열 수 있다.

```text
(1/0 oplus 0/1) + (1/0 oplus 0/1)
```

또는 더 안전하게:

```text
(1/1) + (1/1) → 2/1 → 표시값 2
```

여기서 초기 이해였던 “하나에 하나를 더하면 이어진 하나가 된다”는 틀린 것이 아니다.

그것은 결과값의 관점이 아니라 연결구조의 관점이었다.

```text
계수 관점: 1+1=2
연결 관점: 하나와 하나가 이어져 하나의 연결구조가 된다
```

## 14. Dot and point / line

현재 흐름에서 점과 dot도 분리된다.

```text
점 = 표시된 자리
끝점 = 한 선분의 경계점
교차점 = 두 선분이 만나는 점
직교점 = 두 선분이 직각으로 만나는 점
dot = 관계가 발생하며 드러나는 event 자리
```

선의 끝점은 dot이 아니다.

하지만 그 끝점이 다른 선분, 다른 영역, 다른 frame과 접속되면 dot처럼 작동할 수 있다.

또한 상위 layer에서는 선 전체가 하나의 dot처럼 작동할 수 있다.

```text
하위 layer:
dot + dot → line

상위 layer:
line as existence → dot-like unit
```

따라서:

```text
dot은 선의 끝에 붙은 점이 아니라,
서로 다른 상태가 관계를 맺는 순간 그 경계에서 드러나는 자리다.
```
