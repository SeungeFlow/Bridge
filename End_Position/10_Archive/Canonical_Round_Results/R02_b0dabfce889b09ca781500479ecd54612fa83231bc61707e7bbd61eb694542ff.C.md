# 2. 글자 자체를 도형으로 볼 수 있는가

## 2.1 세 층을 분리한다

### 글자 Object

```text
특정 Source·Snapshot에 나타난 하나의 글자형태
```

필수 Identity:

```text
문자열 또는 이미지 Source
글자 경계
글꼴·필체·판본
방향
해상도
원본/전사 여부
```

### 글자 구조운반체

```text
글자의 경계 안에서 관찰되는
부분·획·여백·배치·접촉·교차·분기·폐합의 배열
```

글자 Object를 의미나 음가로 먼저 고정하지 않고, 보이는 관계를 추출할 때의 역할이다.

### 글자구조 원형

```text
하나의 글자형태에서 추출된 관계를
Carrier와 분리해 Typed Relation으로 재조립한 구조
```

따라서:

```text
글자 Object
≠ 글자구조 원형

글자 Object
→ 구조운반체로 관찰
→ 관계 추출
→ 글자구조 원형 후보
```

## 2.2 “도형”의 두 의미

### 압축된 구조도형

글자 자체가 가진 가시적 관계구조다.

```text
획
부분
여백
상하·좌우
교차
분기
열림·닫힘
```

### 명시적 기하도형

관계를 점·선·축·경계·면·영역으로 외부에 펼친 표현이다.

```text
압축된 글자구조
→ 명시적 도형전개
```

따라서:

> **글자는 도형으로 바뀌기 전에는 아무 구조도 없는 언어기호가 아니다. 글자는 이미 구조관계를 압축해 가진 구조운반체이며, 명시적 도형은 그 관계를 확대·분리·검산하는 외부화다.**

## 2.3 구조원형이라는 말의 범위

`글자구조 원형`은 다음 프로젝트 역할을 뜻한다.

```text
의미 이전에도 관찰 가능한 관계
분해해도 원본계보를 보존할 수 있는 구성
재조립 가능한 최소관계
다른 Carrier로 옮긴 뒤 역복원 가능한 구조
```

이는 다음 보편역사 주장이 아니다.

```text
인류의 모든 도형은 글자에서 나왔다
모든 글자는 하나의 자연법칙을 담는다
```

# 3. 파자의 정식 정의

## 3.1 일반 파자와 구조 파자의 구분

이번 프로젝트에서 사용하는 분석연산은 `구조 파자`다.

```text
구조 파자
=
완성된 표면단위를 원형 그대로 잠근 뒤
후보경계를 따라 부분으로 분해하고
각 부분의 형상보다 관계를 추출한 뒤
원본계보를 유지하며 다시 조립하는 연산
```

어원·훈고·역사자형을 확정하는 전통적 파자와 자동으로 동일시하지 않는다.

```text
구조 파자
≠ 역사적 자원 해석의 자동증명
```

## 3.2 구조 파자 연산순서

### 원형 잠금

```text
원래 나타난 문자열·글자·이미지를 변경하지 않는다.
```

### 외부경계 고정

```text
한 글자
여러 글자의 열
단어
문장
배열
```

가운데 어느 범위를 분석 Object로 선택했는지 명시한다.

### 분절후보 생성

```text
획
구성부분
공유선
교차
여백
반복단위
```

경계가 하나로 확정되지 않으면 복수후보를 보존한다.

### Carrier Inventory

각 부분이 실제로 무엇으로 보이는지 기록한다.

```text
직선형
곡선형
점형
열린 부분
닫힌 부분
교차부분
분리부분
```

### Relation Extraction

형상명보다 관계를 추출한다.

```text
위·아래
안·밖
접촉·분리
교차
연결
분기
반복
열림·폐합
```

### Typed Recomposition

추출관계를 원래 순서·자리·계보와 함께 다시 조립한다.

### 의미 후대조

구조결과와 기존 의미·음가·용례를 독립적으로 비교한다.

### 역복원

재조립된 관계만으로 원래 글자 Object의 핵심배치를 복원할 수 있는지 시험한다.

### Correction Lineage

오독·대체분절·실패한 재조립을 삭제하지 않는다.

## 3.3 파자의 두 방향

```text
전체 → 경계 → 분절 → 최소관계
```

그리고:

```text
최소관계 → 조합 → 전체복원
```

두 방향을 모두 통과해야 한다.

```text
분해만 성공
≠ 구조원형 형성

재조립만 가능
≠ 원래 Object에서 나온 구조라는 증명
```

# 8. 글자구조 → 도형구조 Handoff

## 8.1 Handoff의 목적

```text
글자의 외형을 닮은 도형을 찾는 것
```

이 아니라:

```text
글자에서 추출된 최소관계를
다른 Carrier에 옮겨도 보존되는지 검산하는 것
```

이다.

## 8.2 Handoff 순서

```text
글자 Object Identity 잠금
→ 구조 파자
→ GLR Typed Relation 추출
→ Carrier 비종속 관계 선택
→ 도형 Carrier 지정
→ 전방 생성
→ Residual 기록
→ 역복원
```

## 8.3 Carrier 치환표

| 글자구조 관계 | 도형 Carrier 후보 | 자동동일성 |
|---|---|---|
| 부분자리 | 기점·영역 | 금지 |
| 획의 연장 | 관계선·축 | 금지 |
| 교차 | 교점·통과관계 | 조건부 |
| 분기 | 복수방향·면분화 | 조건부 |
| 둘러싸임 | 폐합경계·영역 | 조건부 |
| 여백 | 빈 영역·내부공간 | 조건부 |
| 반복 | 재귀연산·주기 | 조건부 |
| 상대자리 | 좌표·국소 Frame | 조건부 |
| 결합 | 접합·공유경계 | 조건부 |
