# Principle_C — Start_Position·Center_Position·End_Position 전체 구조정리

## 0. 문서 목적

이 문서는 `SeungeFlow/Principle_C`의 다음 세 Position Branch를 하나의 구조원리로 정리한다.

```text
Start_Position
Center_Position
End_Position
```

`Before_Position`은 이번 범위에서 제외한다.

이번 정리는 기존 Branch와 파일을 즉시 이동·병합·삭제하는 실행지시가 아니다.

```text
기존자산 보존
→ Branch 역할분리
→ 정본 소유권과 참조관계 고정
→ 목표 Tree 형성
→ 후속 GitHub 작업의 기준문서로 사용
```

# 1. Principle_C 전체 구조원리

## 1.1 세 Position의 핵심 역할

```text
Start_Position
=
구조원형
+ 원리의 시작자리
+ 직접 정의
+ 최소구조성질
+ Principle Seed

Center_Position
=
분석기법
+ 분석진행과정
+ 분석재료
+ 반례·검산·Correction
+ 독립 재적용

End_Position
=
Center_Position을 적용해 형성한 Result
+ 검산된 핵심
+ 조건부·충돌·미해결
+ 다음 Cycle을 위한 환류후보
```

## 1.2 전체 흐름

```text
구조원형·Principle Seed
(Start_Position)
↓
분석기법·과정·재료 적용
(Center_Position)
↓
구조해석 Result
(End_Position)
↓
Closure 검산
↓
End가 다음 시작과 교차하는 경우
Next Start Candidate
```

## 1.3 중심명제

```text
Start_Position is not Center_Position.
Center_Position is not End_Position.
End_Position is not automatic promotion.
relation is not merge.
```

세 Branch는 같은 자료를 중복 보관하는 주제별 폴더가 아니다.

각 Branch는 동일한 구조 Cycle에서 서로 다른 역할을 맡는 별도 Position Asset이다.

# 2. Start_Position — 구조원형과 Principle Seed

## 2.1 정식 역할

`Start_Position`은 Principle_C의 Repository Entry Door이자 구조원리가 실제로 시작되는 자리다.

과거에는 다음 역할이 함께 놓여 있었다.

```text
Method
Principle
Criterion
Observer Position
Difference Detection
Spin / Round
Linearization
Unfolding
Reverse Validation
Structure Interpretation
```

세 Position이 분리된 이후에는 이 가운데 다음을 `Start_Position`의 핵심 소유영역으로 고정한다.

```text
Principle
Criterion
구조원형
최초 관찰자리
직접 사용자 정의
최소구조성질
원리의 형성계보
```

분석 실행방법·Casebook·반례시험·독립 재적용은 `Center_Position`이 소유한다.

## 2.2 글자구조의 위치

이번 구조에서 글자구조는 도형구조와 병렬인 하나의 사례가 아니다.

```text
글자 자체를 의미 이전의 구조도형으로 볼 수 있는가
→ 글자를 파자로 분해
→ 획·자리·교차·분기·경계 추출
→ 최소구조성질 재조립
→ 명시적 도형으로 전개
```

따라서 `Start_Position`은 다음을 소유한다.

```text
글자구조 원형
글자를 구조도형으로 읽는 최초 질문
파자 기반 구조분해
구조관계 재조립
도형전개 이전의 최소구조성질
```

## 2.5 기존 73개 파일의 처리원칙

기존 `Start_Position` 자산은 자동이동하지 않는다.


# 5. 세 Branch의 자산 소유권

| 자산 유형 | Canonical Owner | 다른 Branch의 관계 |
|---|---|---|
| 구조원형·직접 정의 | `Start_Position` | Center는 분석, End는 Source Snapshot |
| 글자 파자·최소구조성질 | `Start_Position` | Center는 Method Binding, End는 적용결과 |
| 분석기법·관찰축 | `Center_Position` | Start는 형성계보만, End는 적용기록 |
| 분석재료 Registry | `Center_Position` | Start Source와 Hash 결속 |
| 반례·시험·재적용 | `Center_Position` | End가 시험결과를 인용 |
| 특정 Source 분석결과 | `End_Position` | Start/Center에는 Feedback 후보만 |
| Correction Lineage | Source별 Result는 `End_Position` | Method-level Correction은 승인 후 Center |
| Next Start Candidate | `End_Position/09_Continuity` | Closure 후 Start 갱신 후보 |
| Branch Identity·Guard | 각 Branch 자체 | 상호 대체 금지 |

# 6. 같은 파일의 세 Branch 사용규칙

## 6.1 Canonical Ownership

하나의 Source는 원칙적으로 하나의 Canonical Owner를 둔다.

```text
0fd8... Source
→ Canonical Principle Owner: Start_Position
```

## 6.2 Center 사용

`Center_Position`은 Source를 Method로 바꾸지 않고 다음을 기록한다.

```text
Source Hash
Authority
Material Class
Method Binding
Evidence State
```

## 6.3 End 사용

`End_Position`은 재현성을 위해 분석 당시의 Exact Source Snapshot을 보존할 수 있다.

이 Snapshot은 새 Canonical Source가 아니다.

```text
Exact Snapshot
=
Result 재현용 봉인 Input
```

## 6.4 금지

```text
동일 내용의 무표시 복사
Branch별 다른 내용에 같은 Identity 부여
Source와 Result를 같은 파일로 병합
Hash가 다른 파일을 같은 정본으로 취급
```

# 8. 전체 Cycle

## 8.1 Principle Formation

```text
사용자의 직접 구조직관
→ 글자 자체를 구조도형으로 관찰
→ 파자
→ 최소구조성질 추출
→ Start_Position Principle Seed
```

## 8.2 Analysis

```text
Start Principle Seed
+ Source
→ Center Method Routing
→ Multi-axis Analysis
→ Rendering/Cycle/Center/Evidence/Failure 검산
```

## 8.3 Result

```text
Center Analysis
→ End Result
→ Validated / Conditional / Conflicted / Unresolved 분리
```

## 8.4 Closure와 Next Start

```text
End Result
→ Closure 검산
→ End와 Closure의 교차
→ Next Start Candidate
```

Next Start Candidate는 자동으로 `Start_Position` 정본이 되지 않는다.

```text
Candidate
→ 독립검산
→ 사용자 승인
→ 새 Start Cycle
```
