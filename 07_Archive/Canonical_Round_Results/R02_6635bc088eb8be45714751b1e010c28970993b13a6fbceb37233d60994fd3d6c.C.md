# gpt.lang Center_Position R02 — 분석기법 원자와 관찰축

## 1. R02 목적

기존 58개 Method와 R03-R05에서 형성된 렌더링·최소관점 규칙, 그리고 사용자가 추가한 Cycle·현실/추상·Method–Axis 정의를 하나의 수준으로 섞지 않고 해체한다.

```text
기존 Method 이름
→ 재사용 가능한 최소 관찰기능 원자
→ 원자가 여는 주 관찰축
→ Blind Region
→ 필요한 Evidence
→ 같은 축·보완축·충돌축 관계
→ R03 Method Combination 입력
```

## 3. 용어의 층

### 3.1 Analysis Atom

도메인 사례와 분리해 재사용할 수 있으며 입력·관찰층·출력·Blind Region·Evidence Gate를 독립 기록할 수 있는 최소 기능이다.

### 3.2 Method

하나 이상의 Atom을 정해진 순서와 조건으로 묶은 실행기법이다.

### 3.3 Observation Axis

Method가 선택한 기준·대조·방향·경계 위에서 차이를 배열하는 관계축이다. 반드시 물리적 공간축일 필요는 없다.

```text
Axis
=
Reference
+ Typed Domain
+ Contrast/Order
+ Boundary
+ Evidence State
```

### 3.4 Method Combination

문제에 필요한 복수 Method·관찰축·순서·조건·Evidence Gate·Failure Boundary의 결합이다.

### 3.5 Meta Frame

Rendering Analysis처럼 복수 관찰축을 배치하고 관계검산하지만 개별 Object-level Method를 대신하지 않는 상위틀이다.

### 3.6 Support Atom

분석대상에 새 축을 여는 기능이 아니라 Method와 결과를 공유자산으로 지속시키는 기록·인스턴스 계승 기능이다.

## 13. Method–Axis Principal Findings

### 13.1 하나의 Method도 여러 축을 사용할 수 있다

`M23 초성–중성–종성 영역분석`은 순서축, 관계구간축, Snapshot축을 함께 사용한다. 이를 하나의 원자축으로 취급하면 도메인 가설과 일반 Method가 섞인다.

### 13.2 여러 Method가 같은 축을 반복할 수 있다

`M26`, `M27`, `M28`, `M29-M31`은 서로 다른 대상을 다루지만 상당부분 `AX-16 Glyph/Geometry/Topology`를 공유한다. Method 수를 그대로 차원 수로 계산할 수 없다.

### 13.3 검증 Method는 새 객체축이 아니라 통제축일 수 있다

`M54-M58`은 대상의 새 면을 관측하기보다 기존 결과의 반례·오류·Correction을 통제한다. 이들은 `AX-22`를 여는 검증축이며 도메인축과 동등하게 합산하지 않는다.

### 13.4 Rendering은 관찰축이 아니라 축 배치 Meta Frame이다

`MA-025`는 `[xy,z]·[xz,y]·[yz,x]`처럼 여러 Object-level 축을 Local Front로 바꾸고 관계검산한다. Rendering만으로 누락 Source나 새 사실이 생성되지 않는다.

### 13.5 Cycle·Center는 별도의 후행축이다

시작과 끝을 안다고 Center가 자동생성되지 않는다. `AX-09 Cycle Boundary Role`과 `AX-07 Center/Closure`는 경로·전환·후속 시작 또는 반대기점이 충분할 때만 열린다.

### 13.6 Reality와 Abstraction은 단절축이 아니다

`MA-015`는 Reality 자료와 추상연산 사이의 접속을 관측하지만, 추상후보를 Reality로 승격하지 않는다. 두 층은 이어져 있으나 Evidence 상태가 다르다.
