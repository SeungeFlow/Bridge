## 9. Process Lineage as Analysis Material

gpt.logi 운용체계 자체도 다음 분석예시를 제공한다.

```text
1d
독립 Source 수집
↓
2d
두 Seat 자료의 관계·Identity·Authority 검산
↓
3d
세 2d Result의 관계형성·Conflict·Correction·Gap 집계
↓
4d
직접성·권위·사용 Gate·다음경로 최종검수
```

이 Process는 `Center_Position`의 분석재료로 보존하지만 HRTDB_A의 고정 운용규칙을 다른 인스턴스에 강제하는 문서로 변환하지 않는다.

### 9.1 Process에서 얻는 분석예시

- 같은 Source도 X/Y/Z Seat에서 다른 관찰축을 가질 수 있다.
- 2d 관계검산은 1d 자료를 병합하지 않고 차이와 충돌을 보존한다.
- 3d Result는 Source를 새로 만들지 않고 관계·수량·Correction을 형성한다.
- 4d Final은 문서의 수준이 아니라 사용가능 권위와 다음경로를 검수한다.
- 예정 Handoff와 실제 사용자 승인경로가 다를 수 있으므로 후행 권위교정을 보존해야 한다.

## 10. Raw–Normalized Asset Rule

```text
Raw
→ 원래 표기·바이트·Source 위치·렌더링 의존 보존

Normalized
→ 비교·검색·기계분해를 위한 변환

Lineage
→ Raw에서 Normalized로 간 연산·손실·Correction 기록
```

Normalization은 역사계보·표준자형·의미동일성의 증명이 아니다.

PUA 옛한글은 다음을 함께 기록한다.

- Raw codepoint
- font/rendering dependency
- reference image 필요상태
- 자동 현대문자 대체 금지

## 11. Conflict·Correction·Gap Asset Rule

### Conflict

동일 Typed Object에 양립할 수 없는 Position 또는 서로 다른 권위층이 존재함을 기록한다.

### Source-Scope Difference

서로 다른 Source가 다른 층을 말하여 직접 모순이 아닌 경우다.

### Correction

```text
Original
→ Detected Error/Limit
→ Correction Basis
→ Append-only Current Relation
```

### Gap

```yaml
Source_Gap:
  해결방법: 추가 Source·Stable ID·Facsimile·직접 관측

Method_Gap:
  해결방법: 선택규칙·정량기준·Cycle/Center Gate 형성
```

누락은 분석결론이 아니며, Conflict는 삭제대상이 아니다.
