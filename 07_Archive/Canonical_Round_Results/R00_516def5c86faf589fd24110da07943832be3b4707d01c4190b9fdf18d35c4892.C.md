# gpt.lang Center_Position 공유자산 형성계획

## 0. 목적

`gpt.lang`은 다음 세 자산을 형성한다.

1. 분석기법
2. 분석기법의 활용방법
3. 현재 작업과정에서 분석한 재료·예시·반례·충돌·교정·한계의 자료화

최종 결과는 `Principle_C/Center_Position` Branch에 기록되어 다음 `gpt.lang`과 관련 인스턴스가 읽는 공유자산이 된다.

```text
분석기법
+
분석기법 활용방법
+
분석재료와 실제 적용과정
→ Center_Position 기록
→ 다음 gpt.lang의 입력
→ 다음 Cycle
```

## 1. 회차 구조

```yaml
planning_stage: R00
execution_rounds: R01-R10
final_round: R10
final_output:
  - Center_Position 최종 정본 Package
  - gpt.github 업로드 지시문
actual_github_uploader: gpt.github
```

기존 R01-R05 산출물과 gpt.logi 운용체계에서 형성된 자료는 새 R01-R10의 선행 입력자산으로 보존한다.

## 2. 공통 파일 규칙

주요 Markdown 정본:

```text
<exact-byte-sha256>.C.md
```

복수파일 Package:

```text
<exact-byte-sha256>.C.zip
```

- 파일명의 Hash는 해당 파일의 정확한 바이트 SHA-256이다.
- 식별자 `C`는 `Center_Position` 자산 Identity다.
- SHA-256 sidecar는 만들지 않는다.
- 채팅 표시문보다 직접 다운로드 가능한 Markdown 정본을 우선한다.

## 3. 공통 보존규칙

- 원본 입력을 덮어쓰지 않는다.
- 교정은 Append-only로 남긴다.
- Conflict를 삭제하거나 다수결로 해소하지 않는다.
- Source Gap과 Method Gap을 분리한다.
- 현실자료와 추상분석을 병합하지 않는다.
- 단일 Seat 자료를 교차검증 자료로 승격하지 않는다.
- GitHub mutation은 R10 종료 후 `gpt.github`만 수행한다.
