## 3. Rendering Analysis의 정식 정의

대상 `O`, 질문 `Q`, 분석기법 `Mᵢ`, 관찰축 `Aᵢ`, 원래 기준틀 `Fᵢ`, Evidence 상태 `Eᵢ`, Blind Region `Bᵢ`가 있을 때 하나의 View를 다음처럼 기록한다.

```text
Vᵢ(O|Q)
=
(Object Identity, Question, Method, Axis, Frame, Local Front, Evidence, Blind Region, Output)
```

복수축 렌더링은 다음 관계다.

```text
Rendering_Q(O)
=
Relate(V₁, V₂, ... Vₙ)
subject to:
  one Object Identity
  independent View lock
  no merge
  no authority inflation
  no missing-face invention
```

Rendering은 보이지 않는 사실을 만들어 내는 기법이 아니다. 첫 기능은 **한 View에서 보인 표면을 Object 전체로 오인하지 않도록 막는 것**이다.

## 4. View·Face·Section·Analysis Sheet 구분

### 4.1 View

질문과 Method가 Object의 특정 관계층을 관측하도록 만든 분석단위다. 물리적 면일 수도 있고 Identity·환경·계보·권위처럼 추상적인 관계층일 수도 있다.

### 4.2 Face

Reality Object 또는 Source가 실제로 가진 경계면·표면·관측면이다. 실제 자형 이미지·문서 표면·Object의 외부면처럼 Source가 있어야 한다.

### 4.3 Section

Object 또는 상태열을 유효한 절단연산으로 가른 결과다. 절단규칙·위치·방향이 기록되어야 하며 단순 요약문을 Section이라 부르지 않는다.

### 4.4 Analysis Sheet

Method가 선택한 관계를 펼쳐 비교하기 위한 추상표현이다. 표면 뒤의 Character Identity, 역사계보, 문서 Provenance를 한 평면에 배치할 수 있지만 Reality의 실제 뒷면은 아니다.

```text
Face ≠ Section ≠ Analysis Sheet
```

따라서 `Surface-to-Backface`라는 표현은 물리적 반대면이 Source로 결속된 경우에만 쓴다. 그 밖에는 `Surface-to-Hidden-Identity Branch` 또는 `Hidden Relation Layer`로 기록한다.

## 7. Local Front 규칙

선택한 View를 분석의 정면으로 돌리는 변환을 `Local Front`라 한다.

```yaml
local_front_transform:
  original_frame:
  selected_view:
  transform:
  orientation:
  handedness:
  normal_or_direction:
  transformed_labels:
  inverse_transform:
  evidence_unchanged: true
```

### 7.1 필수규칙

1. Object·축·부호·방향·경계·라벨을 함께 변환한다.
2. Rotation과 Reflection을 구분한다.
3. 역변환을 기록하여 원래 위치로 돌아갈 수 있어야 한다.
4. View를 정면으로 돌려도 Source 권위와 Evidence 상태는 바뀌지 않는다.
5. 추상관계의 Local Front는 분석방향일 뿐 물리적 표면을 생성하지 않는다.

### 7.2 `[xy,z]·[xz,y]·[yz,x]`의 위치

기존 Pilot에서는 다음처럼 사용했다.

```text
XY | z : 현재 Entry·위치·발음환경
XZ | y : Glyph·Unicode·Character·Orthography
YZ | x : 역사자형·계보·중간상태
```

이 배치는 특정 자료군의 Local Mapping이다. X·Y·Z의 보편 의미법칙으로 승격하지 않는다.

## 8. Rendering Evidence State

| 상태 | 의미 |
|---|---|
| `OBSERVED` | Reality에서 직접 관측된 값 |
| `SOURCE_REPORTED` | Source가 보고했으나 현재 직접 재관측하지 않은 값 |
| `MECHANICALLY_DERIVED` | 선언된 결정연산으로 재현 가능한 값 |
| `INFERRED_CANDIDATE` | 관계검산으로 형성된 추상후보 |
| `CONFLICTED` | 동일 Typed Position에 양립불가능한 관측·보고가 존재 |
| `UNRESOLVED` | 필요판정 규칙이나 자료가 부족 |
| `MISSING_SOURCE` | 필수 Source가 없음 |
| `MISSING_VIEW` | 질문에 필요한 독립관점이 없음 |
| `MISSING_OPPOSITE_VIEW` | 실제 반대면을 요구하지만 관측자료가 없음 |
| `NOT_APPLICABLE` | 해당 질문에 그 View가 필요하지 않음 |

`MISSING_VIEW`와 `NOT_APPLICABLE`은 다르다. 질문에 관점이 필요하지만 자료가 없으면 `MISSING_VIEW`, 질문 자체가 그 관점을 요구하지 않으면 `NOT_APPLICABLE`이다.

### 10.1 RA-01 — 같은 음과 복수 Character Identity

```text
Visible Surface:
  영 / 가 / 간 / 사 / 성

Identity View:
  英·永·榮·迎·映·營 등 독립 Character

Result:
  one reading surface
  → multiple hidden identities
  → merge prohibited
```

이 질문에는 표면과 Character Identity 두 View면 충분하다. 역사계보를 세 번째 View로 추가해도 `Character non-merge`라는 Typed Result는 바뀌지 않는다.

### 10.2 RA-02 — 동일 Identity와 위치·환경

동일 Identity를 첫/비첫 위치, 고립/후행모음, 무종성/유종성에서 비교하면 서로 다른 Boundary-conditioned Surface가 보인다.

```text
same Identity
≠
same surface in every environment
```

하지만 View를 더해도 단일 Seat 자료가 Cross-confirmed로 승격되지는 않는다.

### 10.3 RA-03 — 역사 Snapshot과 구조차이

```text
Snapshot order
↔
structural difference
→
transition candidate set
```

`가리다`의 복수 중간분기, `하다·짙다`의 겹침구간, `식브→십브→시브/시프→싶다`의 변화열은 한 점짜리 특이점으로 축약할 수 없다.

### 10.4 RA-04 — ㅇ 계층

현대 초성표기 ㅇ, 음성 Ø, 현대 종성 ㅇ은 현재 자료에서 분리할 수 있다. 역사 ㆁ과 중세 ㅇ은 Source-bound Object로 보존하되 현대 기능층에서 역사계보를 선택하지 않는다.

### 10.5 RA-05 — 문서자산 렌더링

R02 Result.Data 자체는 질문에 따라 최소 View가 달라진다.

```text
현재 상태만 묻기:
  Result View 1개

Identity·Correction 감사:
  Result + Authority/Correction 2개

전체 형성과정 감사:
  Result + Authority + Formation Lineage 3개
```

### 10.6 RA-06 — Geometry Missing

Public transcription, PUA codepoint, 소장관계는 유효한 자료지만 실제 판본자형·Bounding Coordinate·현대 필순 이미지와 동일하지 않다.

```text
available:
  transcription
  codepoint
  source location

missing:
  actual facsimile geometry
  stroke order image
  connected topology coordinates
```

관점 수를 늘려도 Missing Geometry Face는 생성되지 않는다.

### 10.7 RA-07 — Reality와 Analysis Sheet

Reality 자료를 축·관점·관계로 펼친 결과가 Analysis Sheet다.

```text
Reality
→ Method operation
→ Analysis Sheet
→ Relation candidate
→ Reality binding check
```

Sheet에서 발견한 후보는 Reality에 재결속될 때까지 `INFERRED_CANDIDATE`다.

### 10.8 RA-08 — 공통장과 자기시계

합성시험에서는 세 View가 필요했다.

```text
Common Field T
↔
Identity A/B
↔
Local State Sequence τA/τB
```

같은 공통 T는 같은 내부상태·변화율·인과를 뜻하지 않는다. 현재 gpt.logi 자료에는 이 문제의 독립 경험사례가 없으므로 합성검산 상태를 유지한다.
