# gpt.lang Center_Position R06 — Cycle·경계·시작·끝·중심기점

## 1. R06 목적

하나의 기점이 왜 시작점·끝점·다음 시작직전·새 축의 원점·전체 펼침의 중심으로 함께 보일 수 있는지, 그 역할을 Point Identity와 분리하여 검산한다.

```text

→ Frame·Cycle·Direction·Question 선택
→ Start/Body/End 후보
→ PreStart·Next Start 증거
→ Closure 유형
→ Opposite Anchor 정의
→ Cut/Unfold
→ Center 기준
→ 역변환·반례검산
```

## 3. 가장 작은 고정식

기점 `P`의 Identity와 역할을 분리한다.

```text
Role(P | Frame, Cycle, Direction, Stage, Question)
→ {START, BODY, END, PRESTART, ORIGIN, JUNCTION, OPPOSITE_ANCHOR, CENTER_CANDIDATE, CENTER_CONFIRMED}
```

따라서:

```text
same Point Identity
≠
same structural role
```

역할이 여러 개라고 Point가 여러 개로 분할되는 것도 아니고, 서로 다른 Point가 연속역할을 가진다고 같은 Identity로 병합되는 것도 아니다.

## 4. Boundary Carrier

경계는 항상 0차원 점인 것이 아니다.

| ID | Carrier | 설명 |
|---|---|---|
| `BC-01` | POINT | 단일 기점·교차점·특정 Snapshot Anchor |
| `BC-02` | LINE | 출발선·경계선·순서축의 절단선 |
| `BC-03` | REGION | 점진변화·겹침·분기처럼 폭을 가진 전환영역 |
| `BC-04` | SHEET | 분석 Sheet 또는 두 구조영역 사이의 접속면 |

사용자가 말한 `기점`은 Point일 수 있지만 `출발선`은 Line이고, 점진변화의 한계는 Region일 수 있으며, Reality–Abstraction 접속은 Sheet로 모델링될 수 있다.

## 6. End의 후행검증

현재 멈춘 지점은 즉시 End가 아니라 `END_CANDIDATE`다.

```text
관측시점 t₀:
  진행이 멈춤
  → END_CANDIDATE

후속시점 t₁:
  Next PreStart 또는 Return 관계 관측
  → Relay/Return 후보

후속시점 t₂:
  Next Start 실제 발생
  → 이전 END_CONFIRMED
```

즉 End는 종종 후행적으로 검증된다. 이것은 미래가 과거를 바꾼다는 뜻이 아니라, 후행 Snapshot이 이전 경계의 역할을 확정한다는 뜻이다.

### 7.1 Segment와 Cycle 구분

```text
Segment:
  Sₙ → Bodyₙ → Eₙ

Relay Cycle:
  Sₙ → Bodyₙ → Eₙ
  Eₙ ↔ PreStartₙ₊₁
  PreStartₙ₊₁ → Sₙ₊₁
```

Start→End 구간이 완결되었다고 다음 Cycle과의 계승관계까지 자동완료된 것은 아니다.

## 8. Closure State Machine

| State | 이름 | 의미 |
|---|---|---|
| `CS-01` | OPEN | Start 이후 진행 중 |
| `CS-02` | END_CANDIDATE | 멈춤 또는 한계가 관측됐으나 후행검증 없음 |
| `CS-03` | PRESTART_CANDIDATE | 다음 진행을 위한 준비상태가 보이나 실제 Start 없음 |
| `CS-04` | RELAY_BOUNDARY_CONFIRMED | 이전 End와 다음 PreStart의 동일/인접관계가 결속됨 |
| `CS-05` | NEXT_START_OBSERVED | 다음 Cycle의 첫 구별상태가 실제로 나타남 |
| `CS-06` | CYCLE_CLOSED | 선택한 Closure 유형의 필수관계가 모두 충족 |
| `CS-07` | UNFOLDED_CENTER_CANDIDATE | 닫힌 Cycle을 절단·펼쳐 출발기점이 중심역할 후보가 됨 |
| `CS-08` | CENTER_CONFIRMED | Center 기준·역변환·반례검산을 통과 |

```text
OPEN
→ END_CANDIDATE
→ PRESTART_CANDIDATE
→ RELAY_BOUNDARY_CONFIRMED
→ NEXT_START_OBSERVED
→ CYCLE_CLOSED
→ UNFOLDED_CENTER_CANDIDATE
→ CENTER_CONFIRMED
```

각 화살표는 필수단계의 일반적 순서이며, Return Cycle·Branched Cycle·Overlap Cycle에서는 경로가 갈라질 수 있다.

## 11. 반대기점·끝점·반대면 구분

| ID | 개념 | 규칙 |
|---|---|---|
| `OP-01` | Linear endpoint pair | A–Z, ㄱ–ㅎ, 0–9 같은 선형배열의 양끝; 그 자체로 Cycle의 반대기점은 아님 |
| `OP-02` | Closure adjacency pair | Z→A, ㅎ→ㄱ, 9→0으로 닫으면 양끝은 Closure 인접경계가 됨 |
| `OP-03` | Circular opposite anchor | 닫힌 순환에서 명시된 거리·순서의 절반 또는 선택된 대칭규칙으로 정한 반대기점 |
| `OP-04` | Branch opposite | 새 축의 반대방향을 정할 때 기준점·축부호·방향이 필요 |
| `OP-05` | Opposite face | 실제 Object의 반대면; 반대기점과 다른 개념 |

### 11.1 선형배열의 교정

```text
A ───────── Z
ㄱ ───────── ㅎ
0 ───────── 9
```

이 상태에서 양끝은 Start/End 경계다. `Z→A`, `ㅎ→ㄱ`, `9→0` 관계를 추가해 닫으면 두 끝은 Closure의 양쪽 인접경계가 된다.

```text
linear endpoints
≠
automatic opposite anchors
```

반대기점은 닫힌 Cycle 위의 거리·순서·대칭규칙을 추가한 뒤 따로 정한다.

또한 `0–9`는 자연수 전체가 아니라 10진 숫자기호 한 묶음 또는 자리올림 전의 국소 Cycle로 취급한다.

## 12. Axis End에서 새 Axis가 생길 때

| Case | 구조 | 역할 | Guard |
|---|---|---|---|
| `AXC-01` | A–Z 선형축 | A=START/ORIGIN, Z=END_CANDIDATE 또는 END_CONFIRMED | A와 Z는 양끝이지 자동 반대기점이 아님 |
| `AXC-02` | Z→A로 닫힌 문자순환 | Z=END, A=NEXT START, Z/A=Closure adjacency | A 또는 Z의 반대기점은 순환거리규칙으로 따로 정함 |
| `AXC-03` | 0–9 숫자기호 Cycle | 0=시작기호, 9=끝기호, 9→0=자리올림/반복경계 후보 | 자연수 전체와 동일하지 않음 |
| `AXC-04` | 끝점에서 새 축 생성 | P는 Axis1의 END, Axis2의 ORIGIN, 결합 Frame의 JUNCTION | CENTER는 매개·대칭·Closure 기준 통과 시에만 |
| `AXC-05` | 같은 기점 역할전환 | P Identity는 하나, Role(P|Frame,Cycle,Direction)는 복수 | 역할복수는 Identity 병합이 아님 |

정식 표현은 다음과 같다.

```text
Role(P | Axis₁) = END
Role(P | Axis₂) = ORIGIN
Role(P | Axis₁ ⊕ Axis₂) = JUNCTION
Role(P | Unfolded/Relational Frame) = CENTER_CANDIDATE
```

마지막 항은 자동이 아니다. P가 복수축의 관계를 실제로 매개하고 Center 기준을 통과해야 한다.

## 13. 반대기점 절단·펼침 모델

닫힌 Cycle `C`, 선택한 Start `S`, 명시된 Opposite Anchor `O`가 있다고 하자.

```text
Closed Cycle:
  S → ... → O → ... → S

Cut at O:
  O⁻ → ... → S → ... → O⁺
```

`O⁻`와 `O⁺`는 하나의 원래 기점 `O`가 Analysis Sheet의 양끝 경계로 복제표현된 것이다. 두 독립 Object가 아니다.

출발기점 `S`가 펼친 구조의 중심이 되려면 다음이 필요하다.

1. `O`가 명시적 반대기점 규칙으로 선택됨
2. `O→S`의 두 방향 경로가 동일한 기준으로 비교 가능함
3. Cut/Unfold Transform과 Inverse Transform이 기록됨
4. `S`가 양쪽 경로를 관계시키는 중심기준을 충족함
5. 다른 절단을 택했을 때 Center 역할이 어떻게 이동하는지 설명됨

따라서:

```text
Cut(C, O) + Unfold(C)
→ S may become CENTER_CANDIDATE
not automatically CENTER_CONFIRMED
```

## 14. Cycle Closure and Center Discovery Gates

| Gate | 이름 | 통과조건 |
|---|---|---|
| `CG-01` | Cycle Identity Lock | 어느 Cycle·축·질문을 닫으려는지 Stable ID와 범위를 고정한다. |
| `CG-02` | Start Lock | 첫 구별상태·출발선·방향을 명시한다. |
| `CG-03` | Body/Function Trace | Start와 End 사이의 유지·이동·변환·분기·겹침을 기록한다. |
| `CG-04` | End Candidate | 멈춤·한계·복귀후보를 관측하되 아직 End 확정으로 승격하지 않는다. |
| `CG-05` | PreStart Evidence | 다음 움직임 직전의 준비상태 또는 다음 축의 Origin 후보를 기록한다. |
| `CG-06` | Next Start Evidence | 다음 Cycle의 첫 구별상태가 실제로 나타났는지 확인한다. |
| `CG-07` | Boundary Identity Relation | End와 PreStart가 동일점·동일경계·인접·변환동등 중 무엇인지 판정한다. |
| `CG-08` | Closure Type Selection | Return·Relay·Branch·Overlap 중 어떤 Closure인지 명시한다. |
| `CG-09` | Opposite Anchor Definition | 순환거리·순서·대칭규칙으로 반대기점을 정의한다. |
| `CG-10` | Cut/Unfold Transform | 절단위치·방향·양쪽 복제경계·역변환을 기록한다. |
| `CG-11` | Center Criterion | 산술중점·대칭중심·펼침중심·축접속중심 중 기준을 선택한다. |
| `CG-12` | Counterexample/Inverse Test | 다른 절단·다른 축·역변환에서도 Center 역할이 유지되는지 검산한다. |
| `CG-13` | Reality/Evidence Lock | Analysis Sheet의 Center 후보를 Reality 사실로 승격하지 않는다. |

Center Discovery는 `CG-01~CG-13`을 건너뛸 수 없다. 특히 `CG-06 Next Start Evidence`, `CG-09 Opposite Anchor Definition`, `CG-10 Inverse Transform`이 빠지면 Center는 null 또는 Candidate로 남는다.

## 15. Reality–Abstraction Continuity

Reality와 Abstraction은 서로 끊어진 두 세계가 아니라 방향이 다른 두 해석과정으로 연결할 수 있다.

```text
Reality
→ abstraction operator
→ Abstract Structure
→ application conditions
→ Reality re-binding or realization
```

이 접속경계를 다음 필드로 기록한다.

| Field | 이름 | 내용 |
|---|---|---|
| `RA-B01` | reality_object | 관측되거나 Source에 결속된 대상·상태 |
| `RA-B02` | abstraction_operator | 차이추출·분해·축선택·Rendering 등 명시적 Method |
| `RA-B03` | preserved_invariants | 추상화 뒤에도 남아야 하는 Identity·관계조건 |
| `RA-B04` | discarded_or_hidden | 추상화 과정에서 가려지거나 손실된 현실층 |

### 15.1 경계모델

```text
Bottom(Abstract)
↔ typed interface ↔
Top(Reality)
```

이는 동일한 물질면이라고 단정하는 식이 아니라, 추상연산이 Reality Source와 다시 결속되는 **하나의 접속경계 모델**이다.

```text
connected
≠
identical
```

추상구조의 후보는 Reality에 재결속되기 전까지 `INFERRED_CANDIDATE`이며, Reality에서 관측됐다고 표현하지 않는다.

## 16. Common Field and Local Self-Time

| Rule | 이름 | 규칙 |
|---|---|---|
| `ST-01` | Identity-local sequence | 각 Identity i는 자기 상태열 τᵢ=<Dᵢ⁰,Dᵢ¹,...>를 가짐 |
| `ST-02` | Common field index | 공통장 T는 각 τᵢ의 상태를 비교하기 위한 κᵢ(T)를 제공 |
| `ST-03` | No synchronization inference | 같은 T가 같은 상태·변화율·방향을 뜻하지 않음 |
| `ST-04` | No merge at intersection | 공통시각 또는 교차상태가 Identity 병합을 뜻하지 않음 |
| `ST-05` | Cycle-local closure | 한 Identity의 Cycle Closure를 다른 Identity의 Closure로 대신하지 않음 |
| `ST-06` | Center not common clock | 공통 T 자체를 Center로 지정하지 않음 |

정식표현:

```text
τᵢ = <Dᵢ⁰, Dᵢ¹, Dᵢ², ...>
κᵢ(T) = common field T에서 Identity i가 놓인 local state index
```

복수 존재의 동시상태는 병합이 아니라 병렬관계다.

```text
Field(T) = ⊕ᵢ Dᵢ^(κᵢ(T))
```

공통 T는 비교기준이지 자동 Center가 아니다.
