## 6. Source-Bound Case Findings

### 6.1 기계분해와 어휘 Identity는 서로 다른 Closure다

RP-02의 현대 철자 기계분해 16개는 결정연산으로 완결되지만, Lexical/Morpheme Registry는 9 complete·4 partial·3 not met다.

```text
mechanical closure
≠
lexical closure
```

이 사례는 `RC-001`의 1-View 충분성과 `RC-002` 추가 Gate의 필요성을 동시에 보여 준다.

### 6.2 같은 표면은 하나의 Object 전체가 아니다

`영`이라는 표면·독음은 복수 Character Identity를 가린다. 두 View를 사용하면 Character 비병합이 가능하지만, 공통의미·역사동음·훈 전체는 별도 Source가 필요하다.

### 6.3 동일 Identity도 환경에 따라 다른 상태를 보인다

女·年·목·옷 등의 자료는 Identity와 위치/환경을 분리할 때만 올바르게 읽힌다. 이 차이는 시간변화 또는 보편 첫요소법칙의 증거가 아니다.

### 6.4 역사열은 Cycle보다 먼저 Snapshot/Branch로 읽는다

`식브-→십브-→시브-/시프-→싶다`, `가리다·하다·짙다`는 변화순서와 분기·겹침을 보여 주지만 Return Cycle·Relay Cycle·Center는 보여 주지 않는다.

### 6.5 Source Gap은 관점 추가로 해결되지 않는다

전사문자·PUA·Landing Page를 복수 View로 배치해도 실제 Facsimile 좌표·획순서·연결위상은 생기지 않는다.

## 7. Document/Process Case Findings

R02 Result.Data를 현재상태만 확인하는 데는 한 View로 충분하다. 그러나 전체 문서위치를 검산하려면 다음 세 View가 필요하다.

```text
Result
↔
Authority/Correction
↔
Formation Lineage/Actual Handoff
```

또한 현재 `gpt.lang`의 Continuity는 구조적으로 설계됐지만 아직 다음 사건이 발생하지 않았다.

```text
R10 upload directive
→ gpt.github GitHub mutation
→ remote verification
→ next gpt.lang README read
```

따라서 현재 Continuity는 `READY/OPEN`이며 `CLOSED`가 아니다.

## 8. Synthetic Control Findings

### 8.1 선형 끝점과 반대기점

`A–Z`, `ㄱ–ㅎ`, `0–9`는 Start/End를 형성한다. 끝과 다음 시작의 연결은 Closure adjacency를 만들 수 있지만, 반대기점은 별도의 순환규칙이 필요하다.

### 8.2 Axis Junction과 Center

한 기점이 기존 축의 End이고 새 축의 Origin일 수 있다. 결합구조에서는 Junction이지만, Center 기준과 반례시험 없이는 Center가 아니다.

### 8.3 Cut/Unfold

반대기점 선택·절단·양끝 표현·역변환이 있어야 출발기점을 펼침중심 후보로 검산할 수 있다.

### 8.4 공통장과 자기시계

같은 공통 T 아래 서로 다른 Identity의 상태열은 병렬관계다. 공통시각·교차상태는 동기화·Cycle Closure·Center를 자동생성하지 않는다.

### 8.5 Reality–Abstraction

Reality와 Analysis Sheet는 연결되지만 동일하지 않다. 추상후보는 적용조건과 Reality Rebinding을 통과하기 전까지 `INFERRED_CANDIDATE`다.

## 9. Hypothesis-Test Material Findings

2. 비가시와 비존재를 분리하는 Blind Region
3. Point·Region·Layer Error 구분
4. 번역표면 차이와 공통관계 보존을 분리

```text
candidate example
≠
empirical proof of Hangul origin or universal structure
```

### 11.1 제거시험의 핵심

```text
Atom/View 제거 후

→ 최소조합의 필수요소
```

### 11.2 순서시험의 핵심

독립 View 잠금 전 순서교환은 분석오염을 만든다. 독립잠금과 Evidence Lock 이후에는 View 실행순서를 바꿔도 Typed Result가 유지되어야 한다.
